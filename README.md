# pair-wise-yf-52 戏剧排练台词版本与舞台提示管控

## 源提示词摘要
导演、编剧、舞台监督和演员共同维护不同版本的剧本、角色台词、上下场提示、道具与灯光音效提示。编剧提交后需逐条合并，演员可查看最新版并标记疑问；支持版本对比、单条采纳、批注、冲突处理、排练模式、大字号提词和断网缓存。

## 联排阶段四项关键能力

### 1. 编剧新稿三路合并（`src/app/state/script.merge.ts`）
每行记录 `baseText`（上次与编剧稿同步时的文本），合并时按三路判断：
- **编剧没动的行**（稿文本 === 基准）：整行保留，舞台监督原采纳/退回结论不动。
- **编剧改了、本行还没结论**：新文本自动并入排练稿，基准推进。
- **两边都动过**（编剧改文本 + 舞台监督已采纳/退回或对旧文本下过结论）：挂入该版本的
  `conflicts` 待裁决队列，排练稿文本与结论一律不动，绝不直接盖掉退回决定。
- 待裁决可「采用新稿」（文本推进、重置为待确认重新定性）或「保留排练稿」
  （退回等结论保留、仅对齐基准，下轮合并不再重复挂起）。

### 2. 演员离线疑问按序重放
- 离线记的疑问进全局 `outbox`，每条带 `revisionSeq`（记录时各自取号）、目标版本/行、
  记录时的行文本快照。
- 恢复网络（或手动点重放）后**严格按修订序号排序**，在重放那一刻的最新排练稿上逐条重新比对：
  行文本已变的疑问标 `stale`（过期，仅作参考挂在该行），不把任何旧结论盖回新稿；
  目标版本/行消失的标 `gone`，记录保留不丢。

### 3. 待裁决随版本隔离
冲突队列挂在各自 `ScriptVersion` 上；离线疑问也携带目标版本 id。
合并、裁决、重放都只作用于对应版本，切到别的版本不会串台，再切回来冲突还在。

### 4. 历史存档迁移
`migrateState()` 在每次加载/导入时运行：
- 无 `schemaVersion` 的旧整体存档、只含单个旧版本的导出文件都能打开（当前 schema = 2）。
- 历史行没有稳定标记：按「版本 + 角色 + 出场序号」用确定性 FNV-1a 哈希派稳定 id 并回填 `baseText`。
- 台词、提示、结论、批注一条不丢；迁移版本打 `legacy` 标记，照常版本对比与进入大字号提词。

## 技术栈与其他
Angular + TypeScript + Angular Material + NgRx + RxJS + Transloco。
- 版本对比（`script.compare.ts`）按稳定行标记对齐；标记对不上时退化为同角色按出场序配对。
- 排练提词模式：大字号、深色背景，已退回行不进提词并单独列出。
- 支持导入编剧稿 JSON（`lines: [{id?, role, text, baseText}]`）与历史存档 JSON。
- 状态经 NgRx 管理并持久化到 localStorage（`yf52-script-state`）。
- 核心逻辑验证脚本：`scripts/verify-logic.ts`（33 项断言，经 esbuild 打包后 node 运行）。
